# Security policy

Purify works with user files, so security and data safety are part of the product—not an afterthought.

## Reporting a vulnerability

Please do **not** open a public issue for a security vulnerability. Use GitHub's [private vulnerability reporting form](https://github.com/Mahdi-mortazavi/purify/security/advisories/new) and include:

- the affected version or commit;
- a clear impact statement;
- safe reproduction steps that do not include personal files;
- any suggested mitigation.

If private reporting is unavailable, open an issue with the smallest possible description and ask for a private channel. We will acknowledge reports within seven days and keep the reporter updated as we investigate.

## Scope

Reports involving data loss, unsafe cleanup, path traversal, privilege boundaries, dependency vulnerabilities, or unexpected network activity are especially important. Please keep proof-of-concept material minimal and never attach real drive images or personal data.
